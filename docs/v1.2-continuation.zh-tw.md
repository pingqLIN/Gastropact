# 續接與完成 v1.2 任務

Gastropact 將已封存的任務定義、進度與結果證據分開保存。本指南適用於已撰寫並 seal 的 `task-contract.v1.2` 資料包。範本仍需填入專案資料與授權，不能直接當成可執行任務。英文版為權威文件。

## 1. 核對已保存任務

每次交接先進行唯讀接手驗證，將預留欄位替換為已批准路徑：

```shell
python scripts/task_contract.py resume --task <task-dir> --project <project-root>
```

只有取得 `RESUME_OK` 才繼續；核對 task ID、schema version、revision 與 next action。`resume_mode=READ_ONLY_INTAKE` 僅回報保存狀態，不授予執行權。派工前仍須取得動作所需的當前授權並滿足 hard gates。

若回傳 `STOP`，保留資料包並處理所列 mismatch；不可用聊天歷史重建授權，也不可繞過 stale seal、revision conflict 或 audit gap。

## 2. 保存中斷快照

v1.2 checkpoint 記錄中斷，不完成或推進動作。使用剛觀察到的 revision 與目前 action ID，省略 `--completed-action-id`：

```shell
python scripts/task_contract.py checkpoint --task <task-dir> --project <project-root> --expected-revision <revision> --status RUNNING --current-state "Paused at the current action" --next-action-id <current-action-id> --note "Interruption snapshot"
```

僅在已授權更新任務時執行。成功後重新讀取 revision；checkpoint 會增加狀態修訂序號，但保留已完成動作。其他寫入者使用過期 revision 時會被拒絕。

`checkpoint --status PASS`、指定完成動作或改為另一個 next action，都會以 `automation_result_required` 拒絕。v1.0 與 v1.1 保留各自的 checkpoint 規則。舊 v1.2 checkpoint event 若含非 null 的 `completed_action_id`，`resume` 會以 `audit_gap` 停止，工具不會自動改寫或遷移；請保留資料包，使用經審查的恢復程序。

## 3. 派工並提交綁定證據

取得所需授權後執行：

```shell
python scripts/task_orchestrator.py dispatch --task <task-dir> --project <project-root> --owner <owner>
```

依輸出的 envelope 準備[executor result](../schema/executor-result.schema.json)，綁定精確 task、contract hash、state revision、action、workspace baseline 與 lease。證據須使用支援的 verifier，符合必要 evidence classes、成果摘要及大小。成果也須符合動作範圍與來源規則，不能以既有或無關檔案替代本次產出。verification checks 須引用已知 evidence IDs。

```shell
python scripts/task_orchestrator.py submit-result --task <task-dir> --project <project-root> --owner <owner> --result <executor-result.json>
```

動作完成與終態 PASS 都走這條結果路徑。`RESULT_COMMITTED` 是本機狀態轉換回執；工作驗收仍由 task lead 負責。重複提交必須符合既有結果與交易綁定；沿用 ID 但改變內容會被拒絕。本機冪等提交不保證外部副作用只發生一次。

## 4. 驗證行為

儲存庫驗證相依套件可用時執行：

```shell
python -B -m unittest tests.test_task_contract.TaskContractV12ContinuationTests -v
pwsh -File automation/verify.ps1
```

八項續接測試涵蓋唯讀接手、中斷快照、拒絕直接完成或推進、過期修訂序號、舊事件、證據綁定終態結果與重複提交。完整 gate 另涵蓋合成的程序中止恢復與 POSIX 鎖；Windows 會跳過 POSIX 測試。

這些測試不證明實體斷電耐久性、外部 executor 身分、遠端 CI 成功或正式環境驗收。其他限制見 [README](../README.zh-tw.md#適用範圍與限制)。
